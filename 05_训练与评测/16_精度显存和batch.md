# 16 精度显存和batch：一张卡上怎样跑 6B

[目录](../README.md)｜先修：[微调和训练循环](15_微调和训练循环.md)｜下一章：[评测次数和置信度](17_评测次数和置信度.md)

## 1. 数值精度

**BF16 bfloat16** 用 16 位浮点存数值（指数位与 FP32 同宽），把显存占用和计算量都降一半以上。比赛训练全程 BF16，6000D 80GB 单卡才装得下 6B 全量微调。精度降低带来的数值误差靠混合精度机制兜底：敏感的累计量仍用 32 位。

## 2. 显存都花在哪

| 占用项 | 内容 | 大致占比 |
|---|---|---|
| 模型参数 | 6B 权重本身 | 大头之一 |
| 梯度 | 每个参数一份同尺寸梯度 | 与参数同量级 |
| 优化器状态 | 动量等，常为参数的 1-2 倍 | 大头 |
| 激活值 | 中间计算结果，随 batch 增大 | 随 batch 线性涨 |

比赛实际显存峰值约 78.8GB（80GB 卡，几乎顶满）。**OOM（显存不足）** 的三类成因：真不够、碎片化、多个进程争抢；对应解法分别有梯度累积、重置碎片、清理残留进程。

## 3. batch size 的两面

**batch** 是一步训练同时处理的样本数。显存随 batch 增大；泛化也随 batch 变化。比赛第一版用 batch=4 训了 10k 步，模型把演示数据背了下来（过拟合），评测不理想；换成大 batch 后重新训 50k 步才得到最终成绩。

经验规则：数据少、模型大时，倾向大 batch 少步数，让每步看到更多样化的样本。

## 4. 单卡装不下时的替代

全量微调要求参数、梯度、优化器状态全在卡上。显存不够时的常用替代是 **LoRA**：冻结原模型，只训练插入的小矩阵，可训练参数量缩小百倍以上。比赛代码库的 LoRA 支持当时还是半成品，未能用上，这也是后续优化的方向之一。

## 5. checkpoint 占地

每个 **checkpoint（存档）** 包含模型 24G + hf_ckpt 24G + 优化器 26G，约 74G。50000 步每 5000 步存一次，磁盘要预留数百 GB。比赛曾因清理脚本的排序 bug 误删最新 checkpoint，白训一小时——磁盘管理和自动删除脚本必须先 dry-run。

## 6. 练习

按"参数 + 梯度 + 优化器状态"粗算 6B 模型 BF16 训练的显存下限（每参数按 2+2+8 字节计），与 80GB 对比，余量给了谁。再写下你的卡如果只有 48GB，第一优先尝试的方案是什么。
