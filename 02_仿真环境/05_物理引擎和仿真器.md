# 05 物理引擎和仿真器：机器人为什么在电脑里练

[目录](../README.md)｜先修：[本体感觉和动作空间](../01_认识机器人操作/04_本体感觉和动作空间.md)｜下一章：[任务和episode](06_任务和episode.md)

## 1. 真机贵，仿真便宜

真实机械臂一台数万到数十万元，跑坏一个夹爪、撞一次桌面都是真实损失。**仿真器 simulator** 在电脑里重建机器人和桌面场景，让成千上万次尝试发生在虚拟世界里，坏了重置即可。

灵波比赛全程用 **RoboTwin 2.0** 仿真环境评测。参赛者训练好的模型送进仿真器，机器人按模型输出的动作逐拍运动，仿真器负责把动作变成物理后果。

## 2. 物理引擎管什么

**物理引擎 physics engine** 是仿真器的核心，负责三件事：碰撞检测（两个物体何时接触）、接触力计算（夹住物体的力多大）、刚体运动（物体会滑动、翻倒还是静止）。它按固定步长推进，每一小步更新所有物体的位置和速度。

| 名词 | 含义 |
|---|---|
| 刚体 rigid body | 形状不变的物体，仿真中最常用 |
| 接触 contact | 两个物体表面相互触碰的状态 |
| 步长 time step | 一次物理推进的时间长度 |
| 渲染 rendering | 把场景画成图像的过程 |

RoboTwin 底层用 **SAPIEN** 物理引擎，渲染依赖 Vulkan 图形接口。比赛环境里渲染失败会直接导致评测 0%，这是实际部署中最花时间的一类问题。

## 3. 仿真与现实的差距

仿真器对摩擦、材质、光照做了简化，仿真里练成的策略搬到真实机器人可能失灵，这叫**仿真到现实的差距 sim-to-real gap**。缩小差距的常见做法：在仿真里给初始状态加随机扰动，让模型见过更多变化。

## 4. 版本必须锁定

仿真器的物理行为随版本变化。同一模型在 RoboTwin 不同 commit 下评测，成功率可能差很多。比赛要求锁定 commit `13c3c47`，所有评测在同一版本下进行，分数才有可比性。

## 5. 练习

打开任意一个物理小演示（浏览器里搜 pendulum physics demo），改变一次初始角度，观察摆动轨迹。说出：哪部分是物理引擎在算，哪部分是渲染在画。再想想：如果摩擦设成 0，桌面上的方块推一下会怎样。
